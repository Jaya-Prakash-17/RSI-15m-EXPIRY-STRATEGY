# Implementation Plan - Phase 09: Multi-Index Signal Concurrency

Phase 09 focuses on scaling the bot from a sequential single-index processor to a concurrent multi-index engine capable of handling simultaneous signals from NIFTY, BANKNIFTY, and SENSEX with prioritized capital allocation.

## User Review Required

> [!IMPORTANT]
> **Priority Policy**: In this phase, if multiple indices fire a signal at the same time and capital is insufficient for both, the policy will be **NIFTY > SENSEX > BANKNIFTY**.


## Proposed Technical Changes

### 1. Data Layer: Parallel Spot Ingestion
- **[CONC-01]**: Refactor `LiveTrader._process_strategy_logic` to use `concurrent.futures.ThreadPoolExecutor` for fetching spot candles for all active underlyings.
- **[CONC-02]**: Implement a timeout-gated wait to ensure one slow API response doesn't block the entire data pipeline.

### 2. Strategy Layer: Concurrent Scan
- **[CONC-03]**: Parallelize the option candle building and RSI signal generation for each index.
- **[CONC-04]**: Global Signal Deduplication: Ensure that concurrent alerts for different indices don't accidentally over-leverage the same capital pool before the first order fill is recorded.

### 3. Risk Layer: Priority-Based Allocation
- **[RISK-01]**: Implement `CapitalAllocator` to handle simultaneous signal requests.
- **[RISK-02]**: Dynamic Lot Adjustment: If capital is enough for 2 lots total, and 3 signals arrive, allocate to the highest priority indices first.

## Detailed Work Iterations

### Iteration 1: Parallel I/O
- Update `LiveTrader._get_all_spot_snapshots()` to fetch data for all underlyings in parallel.
- Update `LiveTrader._poll_candle_close` to verify closure across all indices (or use NIFTY as the master clock with cross-checks).

### Iteration 2: Concurrent Signal Processing
- Modify `_process_strategy_logic` loop to generate "Signal Tasks".
- Use a pool to execute strategy processing per underlying.

### Iteration 3: Allocation Logic
- Inject `CapitalAllocator` into `LiveTrader`.
- Update `_place_pending_order` to check for "In-Flight" allocation requests.

## Verification Plan

### Automated Tests
- **Multi-Signal Stress Test**: Mock simultaneous RSI breakouts in NIFTY and BANKNIFTY. Verify that orders are placed for both if capital > 60%, or only for NIFTY if capital < 60%.
- **Latency Benchmarking**: Measure total loop time for 1 vs 3 indices. Target: < 1.5s total processing time.

### Manual Verification
- Visual check of logs to confirm interleaved processing start/end for different indices.
