# Phase 06: Execution Fidelity - Partial-Fill & State Reconciliation

## Goals
Implement a robust state machine for order tracking that handles partial fills via weighted average pricing and ensures atomic persistence of execution data.

## Tasks

### 1. Update Pending Order Structure
- **Target**: `live/live_trader.py` (init and monitoring), `execution/trade_tracker.py`
- **Change**: Add `filled_qty` and `weighted_sum` to `pending_entries` dictionary.
- **Verification**: Ensure these fields are persisted to JSON on each update.

### 2. Implement Weighted Average Logic [PFILL-01]
- **Target**: `live/live_trader.py:_monitor_pending_entries`
- **Change**:
    - Detect `PARTIALLY_FILLED` status.
    - Calculate incremental fill (current_broker_filled - previous_stored_filled).
    - Update `weighted_sum += (recent_fill_price * incremental_qty)`.
    - Set `avg_fill_price = weighted_sum / total_filled`.
- **Logic**: Apply this before `_activate_trade_from_pending` is called.

### 3. Authoritative Reconciliation [RECO-01]
- **Target**: `live/live_trader.py`, `execution/order_manager.py`
- **Change**:
    - Modify `_monitor_pending_entries` to only remove from pending once `status == FILLED` or final quantity is reached.
    - Add logic to handle `REJECTED/CANCELLED` by clearing orphans from `pending_entries`.
- **Goal**: 100% agreement between broker status and internal bot state.

### 4. Zero-Fill Hard Reject [SAFE-01]
- **Target**: `live/live_trader.py`
- **Change**: Ensure any incoming `fill_price <= 0` in any status check (partial or full) is logged as CRITICAL and discarded.

## Verification

- Check `trade_tracker.json` content after simulated partials.
